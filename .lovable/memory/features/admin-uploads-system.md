---
name: admin-uploads-system
description: Admin tab to upload/list/delete images and PDFs to /api/uploads/{domain}/{section}/ with public URLs, used by Eventos/Avisos/Convocatoria/Reglas pages with build-time fallback
type: feature
---
El admin (`/admin` → tab "Archivos") permite subir, listar y eliminar archivos directamente al servidor IONOS sin re-deploy. Endpoint PHP: `server/api/uploads.php` con `?section=eventos|avisos|convocatoria|reglas|pdfs` y `?action=upload|delete` (POST). Auth: misma password `admin2025`. Archivos se guardan en `/api/uploads/{domain}/{section}/{filename}` (scope por Host header → multi-tenant). Validaciones: extensión + MIME por sección, máx 15MB, sanitización de nombres. **Reglas por sección:** `eventos`/`avisos` solo imágenes; `convocatoria` mezcla imágenes + PDF (kind `mixed`); `reglas` solo PDF; `pdfs` es bucket legacy (mantenido para back-compat, ya no aparece en el admin UI). Las páginas públicas (`AtraccionesSection`, `AvisosPostersSection`) priorizan los archivos del servidor (`useUploadsList`) sobre los assets de build-time (`posterAssets.ts`); si el servidor está vacío, caen al fallback de `src/assets/{section}/`. **CRÍTICO:** Los previews de admin (`AdminEventos`, `AdminAvisos`) DEBEN usar la misma lógica de fallback que las páginas públicas — leen `useUploadsList(section)` y solo caen a `BUILT_IN_PREVIEW_POSTERS` si está vacío. Si el preview usara solo build-time, el `posterOrder` guardado generaría índices contra el set equivocado y la página pública se vería desordenada. `PreviewFrame` recibe la lista vía prop `posters: string[]`. **Resolución de PDFs (cadena de 3 niveles, sin importar el nombre del archivo):** `Convocatoria.tsx` y `Reglas.tsx` toman el primer PDF de su propia sección (`convocatoria` o `reglas`); si no hay, buscan en el bucket legacy `pdfs/` por nombre exacto (`convocatoria-torneo.pdf` / `reglas-y-cc.pdf`); como último recurso, caen a `/convocatoria-torneo.pdf` y `/reglas-y-cc.pdf` en public/. Esto significa que el admin puede subir cualquier PDF con cualquier nombre y se usará automáticamente. El admin marca el PDF "en uso" con un Badge cuando hay más de uno. El componente `AdminUploads` tiene 4 sub-tabs (Eventos, Avisos, Convocatoria, Reglas) — la sub-tab "PDFs" se eliminó. Convocatoria muestra PDFs como filas e imágenes como grid en el mismo panel. Hooks: `useUploadsList`, `useUploadFiles`, `useDeleteFile` en `src/hooks/useUploads.ts`. El `.htaccess` ya exenta `/api/` del SPA routing, así que las URLs `/api/uploads/...` se sirven como estáticos. Despliegue: subir `server/api/uploads.php` a IONOS (la carpeta `uploads/` se crea sola al primer upload con permisos 0775).
